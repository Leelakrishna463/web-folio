# Product

<!-- impeccable:product-schema 1 -->

## Platform

web

## Users

Two readers at once, both confirmed:

- **Recruiters / HR** skim. Within about five seconds they need name, role, core stack, location, availability
  ("open to senior backend roles") and where the résumé is. Plain-English labels ("About me", "Skills"), never
  bare hardware designators.
- **Engineers** (hiring managers, interviewers) linger. They enjoy hardware drawn accurately: pins, gold
  contacts, DIMM key notches, M.2 keying, RJ45 jacks, PCIe lanes, vias.

## Product Purpose

Personal portfolio for Lee, a backend engineer (Python / Django / PostgreSQL, Bengaluru, ~5 years) targeting
senior backend roles. Success: a recruiter gets the five-second answer and the résumé; an engineer sees taste and
rigour in how the site itself is built (calm, fast, precise). If it feels gimmicky, slow or overloaded, it works
against Lee.

## Positioning

The site is a motherboard. Each section is a real component and the facts live **on the components**: the CPU
lid carries the name and role, RAM chips are skills, SSD NAND chips are roles in time order, GPU memory chips
are projects, the NIC controller is the email. Every part connects only to the CPU (star topology), the way a
backend engineer thinks about systems around a core.

## Capabilities and Constraints

- Section ↔ part mapping is fixed: CPU = About, RAM = Skills, SSD = Experience, GPU = Projects, NIC = Contact,
  plus a bird's-eye board as landing. Confirmed binding.
- Star bus to the CPU; buses straight with 45° bends. Confirmed binding.
- Parts must be recognisable as the real hardware. Confirmed binding.
- Motion stays calm (slow pulses, blinking LEDs, hover linking), honours `prefers-reduced-motion`. Confirmed binding.
- Contact is one channel only: email (plus résumé).
- Content counts the drawings are built for: 4 skill groups × 3 chips + one free slot, 3 roles, 3 projects.
- Design pages live in `design/`; RAM/SSD/GPU/NIC/board are generated by Python in `design/generator/`
  (`python ram.py` etc. on Windows); `lee-cpu.html` is hand-written.
- The visual language (colour, type, materials) is **open to redesign** as of 2026-10-22; only the items above
  are binding.

## Brand Commitments

- Name / domain: lee.sh (lee.dev as alternative). Bits on the buses spell "LEE" in ASCII.
- Rejected forever: terminal-only page, realistic 3D / Three.js parts, curved buses, adjacent-pin comb wiring,
  separate floating info card/box, "plug the cable in" NIC, rear-I/O panel with one port per contact channel,
  TCP-handshake contact page.

## Evidence on Hand

- Real: name (Lee), role, stack (Python, Django, PostgreSQL, Redis, DRF, Celery, SQL, C++), location
  (Bengaluru), ~5 years, open to senior backend roles.
- Not yet supplied, must stay `[bracketed]` placeholders: companies, role titles, years, impact statements,
  project names and outcomes, email, résumé URL, reply time, "next in the pipeline" skill. RAM load levels are
  guesses awaiting confirmation. Never invent these.

## Product Principles

1. The five-second recruiter answer is never sacrificed for the metaphor.
2. Information lives on the hardware, not in cards beside it.
3. Accuracy is the charm: a part an engineer would recognise beats a stylised icon.
4. Restraint: only components that carry content; no decorative extras.
5. The site's own speed and calm are part of the pitch.

## Accessibility & Inclusion

Every fact reachable without the drawing (screen readers, no JS, narrow screens). Muted text contrast ≥ 4.5:1.
Visible focus on everything focusable. Reduced-motion respected.
